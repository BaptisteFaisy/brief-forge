Brief de contexte — application Atlassian Forge

Politique de confidentialité

Cette page dit précisément quelles données l'application traite, où elle va, et qui la voit. Elle est courte parce que l'application est petite : tout ce qu'elle fait tient dans la liste ci-dessous.

1. Qui traite les données

brief-forge (nom d'affichage : « Brief de contexte ») est une application Atlassian Forge développée et publiée par Baptiste Faisy. Elle s'exécute dans la plateforme Atlassian Cloud, sur le site où l'administrateur l'a installée.

L'installation est une décision de l'administrateur du site Atlassian. Seuls les utilisateurs et les sites où l'application est installée sont concernés.

2. Quelles données sont lues

L'application demande à Jira et à Confluence :

  • la description, les commentaires, le statut et les liens d'un ticket Jira ;
  • les pages Confluence liées au ticket, étiquetées decision ou adr ;
  • les tickets liés et leurs changements voisins (commits, demandes de fusion) via Teamwork Graph ;
  • l'identité de l'utilisateur appelant (identifiant de compte Atlassian), afin d'appeler Jira au nom de cet utilisateur et de n'exposer que ce qu'il voit déjà.

L'application n'essaie pas d'accéder à des données en dehors du ticket qui lui est demandé : le contrôle d'accès est fait avant la collecte, au nom de l'utilisateur, et un refus est reporté tel quel dans le brief plutôt que comblé.

3. Ce qui est écrit, et où

L'application écrit dans le stockage de la plateforme Atlassian (Forge SQL et Forge Storage), dans le site où elle est installée :

  • brief — le brief lui-même (markdown et sources) par couple ticket × budget ;
  • readiness — score de préparation et manques détectés ;
  • attempt, review, lesson — comptes rendus d'agents, revues et leçons réutilisables ;
  • claim — réservation d'un ticket par un agent ;
  • access_log — journal des appels d'outils (ticket, outil, identifiant de compte, horodatage), conservé 90 jours ;
  • project_settings — réglages par projet.

Ces écritures contiennent des éléments identifiants : identifiants de compte Atlassian, noms d'auteurs de commentaires, texte de commentaires. Elles restent dans le site Atlassian où l'application est installée, et sont supprimées avec lui.

4. Sortie de données (« egress »)

Aucune. L'application n'appelle aucun service tiers. Le calcul du brief, le score de préparation, le masquage des secrets et les métriques sont exécutés dans le runtime Atlassian.

Une seule option utilise un modèle de langage : la condensation, désactivée par défaut. Elle est activée explicitement par l'administrateur du déploiement (variable BRIEF_LLM_CONDENSATION=1). Dans ce cas, le contenu à condenser est envoyé à l'API Forge LLMs d'Atlassian, c'est-à-dire à un modèle hébergé par Atlassian — les données ne quittent pas la plateforme Atlassian. Le déclencheur de déclenchement est une taille minimale : si aucun élément d'un ticket ne la dépasse, aucun appel n'est fait.

5. Traitement des contenus tiers

Les commentaires et les pages liés sont traités comme des données, jamais comme des instructions :

  • les motifs qui ressemblent à un secret (jeton, clé, mot de passe) sont masqués ;
  • les textes contenant des instructions adressées à un agent sont écartés ;
  • tout écart est signalé dans le brief (« contenu écarté »), pour que labsence soit visible plutôt que silencieuse.

6. Sous-traitants

Atlassian est l'unique sous-traitant : hébergement Forge, Jira, Confluence, Teamwork Graph, et éventuellement l'API Forge LLMs. Aucun autre tiers ne reçoit de donnée de l'application.

7. Vos droits

L'application n'a pas de base de données propre et n'envoie pas de newsletter. L'effacement des données suit celui du site : uninstaller l'application du site supprime les données applicatives qu'elle y a écrites, et l'administrateur du site reste l'interlocuteur pour toute demande d'accès ou de rectification.

Pour toute question : baptiste.faisy@gmail.com. Le code source est public : github.com/Tradoooo/brief-forge.

8. English summary

brief-forge is an Atlassian Forge app that reads a Jira ticket (and the linked Confluence pages and Teamwork Graph changes) as the calling user, and writes the resulting brief, readiness score, agent reports, lessons and an access log into the Atlassian storage of the site where it is installed. It makes no request to any third-party service: the optional LLM condensation (off by default) uses Atlassian's own hosted Forge LLMs, so data never leaves the Atlassian platform. Third-party text is treated as data: secret patterns are masked, instruction-like text is dropped, and every drop is reported in the brief. Uninstalling the app removes the data it wrote on that site. Contact : baptiste.faisy@gmail.com.
